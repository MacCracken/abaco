# Abaco Security Audit — 2026-05-26 (2.2.3)

P(-1) hardening audit under Cyrius 6.0.1. Re-runs the first-party security
checklist over `src/` after the 5.7.23 → 6.0.1 upgrade, closes the heavier open
items from the [2026-04-14 audit](2026-04-14.md), and confirms that audit's
mitigations still hold.

- **Toolchain**: Cyrius 6.0.1
- **Scope**: `src/{core,ntheory,dsp,eval,units,ai}.cyr` (the library surface).
  Vendored stdlib (`lib/`) is upstream's; stdlib concerns are filed there.

## Checklist results

### 1. Input validation — PASS

- **Expression parser** (`eval.cyr`): recursion depth capped (`MAX_DEPTH = 256`,
  [arch 002](../architecture/002-expression-depth-bound.md)); call arity capped
  (32-slot bounded buffer, MED-6); scientific-notation exponent clamped at 308.
- **NL parser** (`ai.cyr`): percent-phrase operands validated as strict numeric
  literals (CWE-917, HIGH-3, 2026-04-14).
- **Currency** (`ai.cyr`): HTTPS enforced, CRLF/control-byte URL guard,
  per-rate plausibility check (finite, >0, <10⁶), empty-after-filter rejection.

### 2. Buffer safety — PASS

- **No fixed-size stack buffers** in `src/` — `grep 'var X[N]'` is empty. All
  working memory is heap (`alloc`), so there is no adjacent-variable
  stack-overflow surface.
- cstring construction follows the bounded `alloc(n+1)` → `memcpy(…, n)` →
  `store8(buf+n, 0)` pattern throughout (25 `memcpy` sites reviewed).
- The arity buffer is `alloc(32*8)` with a hard `nargs >= 32` reject (MED-6).

### 3. Syscall review — PASS

- **No raw syscalls in `src/`** except `sys_exit` in the `main.cyr` smoke entry.
  All I/O routes through stdlib (`lib/http.cyr`, `lib/io.cyr`), so syscall
  argument/return handling is the audited stdlib's responsibility.

### 4. Pointer validation — PASS

- The JSON field extractors (`_jf_find_value` / `_jf_get_string` /
  `_jf_get_object`) are strictly `len`-bounded — verified by the LOW-9b
  truncated-body regression (`test_ccy_truncated_body`): a lying Content-Length
  cannot drive a read past the declared length.

### 5. Command injection — N/A

- No `sys_system` / `exec` in `src/`. abaco shells out to nothing.

### 6. Path traversal — PASS (with caller note)

- The only file I/O is `CalcHistory_save_to_file(h, path)` /
  `load_from_file(h, path)`. The `path` is supplied by the **consumer**, not by
  external/network data. abaco does not synthesize paths from untrusted input.
  *Caller note*: a consumer that passes a user-supplied path must validate it
  itself — per first-party doctrine, the sandbox (kavach) owns that boundary,
  not abaco.

### 7. Known-pattern / CVE review

- **MED-4 (json recursion) — FIXED this audit.** `lib/json.cyr::json_parse`
  recurses once per nesting level with no depth cap (`_jp_parse_value` →
  `_jp_parse_object`/`_array` → `_jp_parse_value`). abaco feeds it the `rates`
  object from a currency endpoint, so a deeply-nested payload from a compromised
  / MITM'd server could exhaust the native stack before any value is read.
  **Fix**: `_ccy_json_depth_ok` bounds nesting at `CCY_MAX_JSON_DEPTH = 8`
  before `json_parse` runs (legitimate fiat-rate maps are depth-1). Regression:
  `test_ccy_deep_nesting_rejected`. Defense-in-depth on top of the existing
  HTTPS guard (which already blocks the MITM vector).
- **LOW-8 (hashmap HashDoS) — residual risk LOW; upstream recommendation.**
  `lib/hashmap.cyr` uses an unseeded content hash, so an attacker who controls
  keys could force collision flooding (algorithmic-complexity DoS, CWE-407).
  abaco's exposure is limited: registry keys are **fixed/trusted** built-ins;
  currency-rate keys arrive only over an HTTPS-validated endpoint; expression
  variable names are **consumer-supplied**, not attacker-supplied. No
  abaco-side change is warranted. **Recommendation filed for the cyrius
  stdlib**: per-process-seeded (SipHash-class) hashing in `lib/hashmap.cyr`.
